## 一 课题定义与选题依据

### 课题名称

中文名称为数据库蜜罐系统。建议在正式报告中使用完整名称：基于 MySQL 协议模拟的数据库蜜罐与攻击行为分析系统。英文名称可写为 Database Honeypot and Attack Behavior Analysis System。

### 一句话定义

本课题设计并实现一个模拟真实 MySQL 服务的诱饵数据库，通过捕获连接行为和 SQL 操作，识别攻击意图，形成攻击者画像，并在 Web 控制台中展示风险和告警。

### 核心问题

数据库课程项目需要体现数据建模、数据写入、查询分析和结果展示。常见的信息管理系统能够完成这些要求，但较难体现网络空间安全学院的专业特点。本项目把数据库同时作为被模拟的攻击目标和系统内部的分析基础，使数据库知识贯穿诱饵数据、日志存储、画像聚合、规则查询和可视化展示。

项目不以对抗真实攻击者为目标，也不追求企业级威胁检测能力。课程范围内的目标是建立一个可运行、可解释、可重复演示的闭环，证明系统能够接收授权测试流量，记录行为，识别典型意图，并给出可以追溯到原始日志的判断结果。

### 选题价值

| 角度 | 具体价值 | 可验证结果 |
| --- | --- | --- |
| 数据库课程 | 覆盖关系模型、主键与索引、事务写入、聚合查询和数据展示 | 能从一次会话追溯到日志、画像和告警 |
| 网络安全 | 把扫描、口令尝试、数据库踩点和数据窃取放入同一条行为链 | 能用授权脚本复现典型攻击模式 |
| 工程实现 | 采用分层架构和可替换模块，控制项目复杂度 | 核心模块可独立测试并完成集成 |
| 答辩展示 | 攻击端和防守端的状态变化直观 | 现场操作后控制台在可接受时间内更新 |

### 基本原则

- 数据库是项目核心。日志、画像、诱饵和告警都必须有明确的数据模型。
- 判断过程可以解释。每个意图标签和风险分都要能追溯到触发条件。
- 先完成最小闭环。高级诱饵联动、工具指纹和更复杂的统计方法属于后续增强。
- 所有演示均为授权模拟。系统不得连接真实业务数据库，也不得使用真实敏感数据。

### 扩充 蜜罐解决什么问题

直接拿真实业务数据库做课堂测试，会把测试操作和真实数据放在同一环境。蜜罐提供一个可交互的虚假目标：授权测试者看到的是预设库表和虚构记录，项目组看到的是一次会话中发生的连接、认证与查询，以及系统给出判断的依据。

例如，测试者登录后浏览表列表。诱饵层返回虚假的表名，后台用同一个会话编号串起连接、认证与查询。控制台显示查询发生的时间和命中的规则。这个例子同时验证诱饵交互、数据关联和判断可追溯。

其中「诱饵数据」是客户端看到的虚假内容，「观测数据」是后台保存的会话、日志和规则结果。客户端与观察者使用不同入口，两类数据有各自的访问边界。

## 二 项目目标与验收标准

### 总体目标

项目完成后，测试者能够使用 MySQL 客户端或脚本访问诱饵服务。系统能够记录该连接对应的认证尝试和 SQL 操作，将事件写入数据库，依据规则更新攻击者画像，并在控制台显示时间线、意图标签、风险分和告警。

选题阶段的目标是证明方案值得做、做得完、展示效果好。后续实现以课堂小组能够在有限周期内稳定完成为准，任何新增功能都不能挤占最小闭环、界面整理和演示排练的时间。

### 最小可交付闭环

1. 诱饵服务监听指定端口并完成 MySQL 基本握手。
2. 系统按配置接受或拒绝诱饵账号，并记录所有认证尝试。
3. 系统支持 SHOW DATABASES、SHOW TABLES 和 SELECT 等演示所需语句，并返回伪造结果。
4. 每次连接和每条 SQL 都形成结构化记录，并通过 session_id 关联。
5. 规则引擎至少识别扫描、爆破、踩点和拖库四类意图，并单独标记破坏性操作。
6. 系统按 IP 聚合画像，计算 0 到 100 的风险分。
7. 控制台可以查看概览、攻击者列表、会话时间线和告警。
8. 项目在隔离环境中完成一套可重复的现场演示。

### 验收标准

| 编号 | 验收项 | 通过条件 |
| --- | --- | --- |
| A01 | 服务可访问 | 授权测试端能够连接诱饵端口并完成握手 |
| A02 | 日志完整 | 连接、认证和 SQL 事件均写入数据库，关键字段无缺失 |
| A03 | 会话可追溯 | 控制台能够按 session_id 展示同一会话的事件顺序 |
| A04 | 规则有效 | 预设测试脚本能够稳定触发对应意图标签 |
| A05 | 画像更新 | 同一 IP 的连接数、查询数、首末时间和风险分正确更新 |
| A06 | 告警生成 | 爆破、拖库或破坏性操作能够生成告警记录 |
| A07 | 诱饵安全 | 所有展示数据均为伪造数据，系统无到真实内网的有效连接 |
| A08 | 演示可复现 | 按照演示脚本重复执行时，结果与预期一致 |

### 可选增强目标

- 识别 sqlmap、Navicat、PyMySQL 等客户端或工具特征。
- 对拖库行为动态增加伪造数据量，对破坏性操作加入延迟响应。
- 支持诱饵节点之间的联动，但所有目标地址仍处于隔离网络。
- 增加地理位置展示、趋势图、规则命中解释和告警处置状态。

### 扩充 分阶段的通过条件

| 阶段 | 输入 | 通过条件 | 现场证据 |
| --- | --- | --- | --- |
| 样本闭环 | 从空库导入三条固定的合成事件：连接、认证、查看表列表 | 同一会话有三条有序日志，只有查看表列表的事件命中 R03 | SQL 查询、规则证据、页面截图 |
| 诱饵闭环 | 一次授权的本地客户端交互 | 客户端收到虚假表列表，后台出现该次交互对应的新会话 | 客户端结果、会话 ID、控制台时间线 |
| 课程交付 | 固定合成样本加本地交互 | 核心规则、视图、事务、约束和四个页面均可单独核验 | 测试矩阵、查询计划、复现记录 |

样本闭环用于证明模块已经接通。诱饵闭环另外验证事件确由本地交互自动产生，两项分别记录。

## 三 系统范围与使用场景

### 范围边界

| 范围 | 内容 |
| --- | --- |
| 必须实现 | MySQL 诱饵服务、关系数据库存储、会话主外键、意图关系表、规则配置、核心视图、事务与索引验证、告警和 Web 展示 |
| 可以增强 | AI 自然语言只读查询与解释、工具指纹、动态诱饵、更多图表和 Docker 编排 |
| 明确不做 | 真实业务数据接入、主动反制、漏洞利用、恶意代码投递、互联网大规模部署和企业级高可用 |

### 系统角色

| 角色 | 职责或行为 | 权限边界 |
| --- | --- | --- |
| 授权测试者 | 通过客户端进行基础诱饵交互，或使用合成事件验证检测 | 访问范围限于隔离诱饵和伪造数据 |
| 系统管理员 | 配置诱饵账号、规则、端口和数据保留策略 | 可查看完整日志和维护配置 |
| 观察者 | 在答辩或测试中查看控制台结果 | 默认只读，不显示完整口令 |
| 规则引擎 | 读取事件并更新画像、风险分和告警 | 不能发起外部攻击或连接真实资产 |

### 典型场景

1. 扫描场景。使用合成连接日志验证频率规则，并核对窗口内的有效查询记录。
2. 口令尝试场景。用固定认证事件样本验证规则；本地交互只验证预设成功和失败结果。
3. 踩点场景。连接成功后执行 SHOW DATABASES、SHOW TABLES 或查询 information_schema。
4. 拖库场景。用合成查询日志提供连续读取和返回行数等统计字段。
5. 破坏场景。用标记为写操作被拒绝的合成日志验证证据与告警。

### 认证策略

基线采用可配置的诱饵账号策略。使用专用虚构账号和测试凭据验证成功认证，使用未知虚构账号验证失败认证。两类结果均记录为认证事件。

### 扩充 场景输入的选择

正常连接、测试账号认证和读取预设表列表可用于本地现场演示。频率类、批量访问类及破坏性行为检测使用带固定时间和预期结果的合成日志验证。合成样本优先保存行为类别、认证结果、统计字段和脱敏证据，便于重复测试。

| 场景 | 观察重点 | 验收边界 |
| --- | --- | --- |
| 基础连接 | 新会话编号与开始时间 | 会话与原始事件可自动关联 |
| 认证 | 预设账号成功与未知账号失败 | 两种结果均可查，凭据不会出现在界面和导出中 |
| 元数据查询 | 显示预设库表及查询记录 | 页面证据能定位到本次查询 |
| 其他检测行为 | 规则对合成日志的预期反应 | 验证命中、未命中、阈值边界和重复处理 |

## 四 总体架构与核心模块

### 分层架构

| 层次 | 主要职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| 诱饵层 | 模拟 MySQL 握手、认证和基础查询响应 | TCP 连接和 SQL 请求 | 伪造结果或模拟错误 |
| 捕获层 | 生成连接、认证、查询和响应事件 | 协议处理过程 | 标准化事件对象 |
| 存储层 | 持久化日志、画像、诱饵数据和告警 | 标准化事件 | 可查询的关系数据 |
| 分析层 | 按时间窗口和规则识别意图并计算风险 | 日志和统计结果 | 标签、分数和规则证据 |
| 展示层 | 提供概览、时间线、画像和告警页面 | 查询接口返回的数据 | 面向答辩和管理的视图 |

### 数据流

1. 测试端与诱饵服务建立连接，系统为该连接生成唯一 session_id。
2. 捕获层记录来源地址、连接时间、认证信息和客户端特征。
3. 测试端发送 SQL，诱饵层决定返回伪造数据、空结果、权限错误或延迟响应。
4. 捕获层把 SQL、执行时间、响应状态和返回行数写入 attack_log。
5. 分析层读取新增事件，更新 attacker_profile，并在满足条件时写入 alerts。
6. 展示层通过只读接口查询日志、画像和告警，形成时间线与统计图。

### 诱饵数据库模块

诱饵数据库负责让访问者看到一个结构合理但完全虚假的业务数据库。它不需要实现 MySQL 的全部能力，只需要覆盖课程演示所需的握手、认证、元数据查询和基础 SELECT。对于 UPDATE、DELETE、DROP 和 INSERT，系统默认记录语句并返回权限不足。这样可以保留攻击意图，同时避免维护复杂的事务状态。

诱饵内容至少包括 users、orders 和 config 三类表。users 提供伪造的账号、邮箱、手机号和密码哈希；orders 提供伪造订单；config 提供看似敏感但无效的连接串、API 密钥和邮件配置。所有值必须可识别为人工生成，不能复制真实人员或系统信息。

### 行为捕获模块

捕获模块把协议过程转换为统一事件。事件至少包含 event_type、session_id、source_ip、发生时间和处理结果。查询事件保存原始 SQL、标准化 SQL、返回行数和响应耗时。认证事件记录测试用户名和认证结果。需要区分不同合成认证样本时，使用测试标识。

### 分析模块

分析模块由规则匹配、时间窗口统计、画像聚合和风险评分组成。规则判断必须输出命中的规则编号和证据摘要。例如，踩点标签不能只写为 recon，还应说明触发语句是 SHOW TABLES 或 information_schema 查询。

### 展示模块

控制台以只读查询为主。首页显示连接数、查询数、告警数和高风险攻击者数量；攻击者列表显示 IP、首末出现时间、意图标签和风险分；详情页按时间顺序展示认证和 SQL 事件；告警页支持按类型、时间和已读状态筛选。

界面范围控制为四个核心页面：首页概览、攻击者列表、攻击者详情和告警列表。视觉设计保持统一配色、清楚层级和适量图表，优先保证演示时一眼能看懂，不增加复杂权限系统、主题系统或大屏编辑器。

### 扩充 模块输入输出

| 模块 | 输入 | 输出 | 交接检查 |
| --- | --- | --- | --- |
| 诱饵 | 授权客户端交互 | 预设结果或受控错误 | 响应对应于虚构业务内容 |
| 捕获 | 已发生的交互与响应状态 | 带唯一编号的标准事件 | 同次连接的事件共享会话编号 |
| 存储 | 标准事件 | 已提交的会话与日志 | 失败可回滚，重试可幂等 |
| 分析 | 当前事件、启用规则及必要统计 | 命中、意图、评分、告警 | 每条派生结果能关联证据 |
| 展示 | 查询结果 | 页面摘要和按时排序的详情 | 与数据库结果一致，已脱敏 |

标准事件建议明确事件编号的生成时机、时区、事件类型、结果状态、可空字段和顺序规则。连接成功与认证成功分别记录。时间线按事件时间排序，同时间戳用持久化的事件序号打破并列。

## 五 数据库设计与数据生命周期

### 设计原则

- 原始事件、连接会话、攻击意图、检测规则和聚合画像分开保存，避免把可查询实体长期塞入 TEXT 或 JSON 列表。
- sessions 是会话主表，attack_log、rule_hits 和 alerts 通过 session_id 建立正式外键关系。
- attacker_intent 一行只保存一个攻击者意图；同一攻击者可以拥有多条意图记录。
- 风险分由确定性的规则命中和权重计算，能够从画像回溯到规则、会话和原始事件。
- 约束、事务、索引和视图都要服务于可演示的业务场景，避免为了数量堆叠数据库对象。

### 核心分析视图

| 视图 | 主要查询技术 | 页面或分析用途 |
| --- | --- | --- |

四个视图必须被控制台或答辩查询实际使用。复杂 SQL 保存在建库脚本中，并为每个视图准备一条可直接演示的 SELECT 查询。

### 事务 幂等与数据约束

1. 事件写入事务。创建或更新会话、写入 attack_log、写入 rule_hits、生成 alerts 和更新画像应作为一个事务执行，任何一步失败都回滚。
2. 演示重置事务。按外键依赖顺序清理规则命中、告警、日志、会话和画像；发生异常时恢复到重置前状态。
3. 幂等控制。每个采集事件携带 event_uuid，并通过 UNIQUE 约束阻止重复写入；重复请求返回已有事件编号。
4. 完整性约束。使用 CHECK 限制分数、计数、状态和时间范围，使用 FK 保证引用对象存在，使用 UNIQUE 防止规则版本、事件和意图重复。

### 复合索引与 EXPLAIN 验证

| 索引 | 字段顺序 | 目标查询 |
| --- | --- | --- |
| idx_log_session_time | attack_log session_id event_time | 按会话重建事件时间线 |
| idx_log_source_time | attack_log source_ip event_time | 按来源和时间范围查询行为 |
| idx_alert_level_time | alerts severity created_at | 筛选近期高等级告警 |
| idx_hit_rule_time | rule_hits rule_id created_at | 统计规则命中趋势 |

项目准备至少两组索引建立前后的 EXPLAIN 截图或结果记录，观察 key、type 和 rows 等字段。演示数据规模以几千至几万条为宜，用于体现查询计划差异，不把压力测试作为课程目标。

### 数据生命周期

1. 生成。协议模块把连接、认证和查询转换为带 event_uuid 的标准事件。
2. 写入。存储模块在事务中维护 sessions 和 attack_log，并保证重复事件不重复入库。
3. 分析。规则引擎读取启用的 detection_rules，写入 rule_hits，更新 attacker_intent 和画像，必要时生成告警。
4. 展示。控制台优先查询核心视图，详情页再读取原始日志和规则证据。
5. 清理。课程测试数据按配置保留，导出前删除口令字段或进行遮盖。

### 扩充 实体关系和数据一致性

- 一个 `sessions` 对应多条 `attack_log`。日志用 `event_uuid` 实现重试去重。
- 一条 `attack_log` 可对应多条 `rule_hits`。规则命中应引用事件、会话和实际规则版本。若命中表同时保存事件和会话编号，应验证两者来自同次会话。
- 一个 `attacker_profile` 可对应多条 `attacker_intent`，用「画像 ID＋意图类型」维持唯一性。来源地址用于数据聚合，页面上的画像代表来源及行为汇总。
- 告警引用会话，建议保留对应命中或可查询的证据编号。告警去重键应与触发条件匹配，并为重放准备测试。

### 扩充 事务与幂等的验收顺序

按照总纲的单事务基线，先识别幂等键，再依次准备会话、事件、规则命中、画像、意图和告警，最后统一提交。相同事件重试时，相关计数和风险贡献保持不变。在测试中让告警或画像写入受控失败，核对事务涉及的表与执行前一致，然后验证原事件可重试成功。

SQLite 使用时，每个业务连接都应启用外键。幂等依赖数据库唯一约束，调用方也应把「已存在」与「本次新增」作为不同结果处理。

### 扩充 视图验证与索引记录

先用一组可以手算的样本建立验收基准，例如两个来源、三个会话、一个会话关联多条日志和告警。多张明细表先分别聚合再关联，检查计数是否因 JOIN 重复。画像的主要意图排序应在分数和时间相同时仍给出稳定结果。

索引对比固定数据、过滤参数和排序条件。MySQL 8 记录 `EXPLAIN` 的访问类型、索引和估算行数；SQLite 记录 `EXPLAIN QUERY PLAN` 的扫描或索引查找信息。报告将计划变化与实际测得的耗时分别记录。

## 六 意图识别与风险评分

### 规则设计原则

规则必须简单、可测试、可解释。规则参数、风险权重、版本和启用状态存入 detection_rules，分析模块只执行已启用版本。初始阈值用于课程演示，不代表生产环境安全基线。

### 初始检测规则

| 规则 | 意图 | 初始触发条件 | 建议权重 |
| --- | --- | --- | --- |
| R01 | scanning | 60 秒内连接不少于 10 次且无有效 SQL | 10 |
| R02 | bruteforce | 5 分钟内认证不少于 8 次且凭据组合不少于 5 组 | 25 |
| R03 | recon | 出现 SHOW DESCRIBE 或 information_schema 查询 | 15 |
| R04 | data_dump | 连续 SELECT 或会话累计返回行数超过阈值 | 25 |
| R05 | destructive | 出现 DROP TRUNCATE DELETE UPDATE 或 INSERT | 35 |

### 风险评分与最终判定

风险分由启用规则的命中权重和封顶策略确定，最高为 100 分。每一分都必须对应 rule_hits 中的规则、事件和证据。风险等级建议为 0 至 29 低风险，30 至 59 中风险，60 至 79 高风险，80 至 100 严重风险。

AI 不参与风险分计算，不修改规则命中，不生成最终风险等级。即使 AI 功能关闭或网络不可用，规则检测、画像更新、告警生成和控制台展示仍应完整运行。

### 意图更新策略

- 同一攻击者可以同时拥有 scanning、recon 和 data_dump 等多条 attacker_intent 记录。
- 命中新证据时更新对应意图的 intent_score、evidence_count 和 last_detected_at。
- 主要意图由 v_attacker_profile_summary 使用分数、最近时间和危害等级排序得出，不长期保存为多值列表。
- 画像页面必须显示规则编号、命中时间和证据摘要，避免只给标签而无法解释原因。

### 扩充 规则生命周期与评分用例

规则配置负责定义阈值、权重、版本和启用状态。一次命中建议保存当时实际采用的版本和权重快照，使历史证据在配置调整后仍可解释。需要重新计算历史数据时，明确重算范围、规则版本和结果口径。

单条合成样本仅命中权重为 15 的 R03 时，可以预期得分为 15。若系统还有其他有效命中，应按评审确认的聚合口径计算。会话风险分和来源画像风险分应明确各自统计范围。验收至少覆盖无命中、单次命中、重复分析、封顶、停用规则和版本切换。

意图是规则根据可见行为给出的标签。在详情页同时提供事件、规则和摘要，例如「本次会话查看了预设表列表，因此命中结构探测规则」。

### AI 可选功能与权限边界

AI 只作为演示增强，用于把自然语言映射到预设的只读查询模板，或解释已有视图和规则证据。AI 不负责核心检测、风险评分和最终判定。

- AI 查询使用只读数据库账户，只允许 SELECT，并限制在批准的核心视图内。
- 首选由 AI 选择预设查询模板，不直接执行任意生成的 SQL。
- 任何 AI 输出都标记为辅助解释；数据库中的规则命中和风险分是正式结果。
- AI 功能属于选做项，接口不可用时不影响最小闭环和现场演示。

### 降级路线

若协议模拟库在规定时间内无法完成稳定握手，项目切换为隔离的真实 MySQL 实例，导入伪造数据，并通过 general_log 或审计机制记录操作。降级后仍保留相同的日志表、画像表、规则和控制台，因此项目主题和数据库设计不变，只替换诱饵层实现。

### 扩充 开发环境和接口细节

统一 Python、内部数据库和 Web 框架的版本，将监听地址、运行数据库路径及演示配置写入样例配置。开发库、自动化测试库和现场演示库可分别配置。说明文档应写明初始化、启动、健康检查与关闭顺序。

接口文档为每个路由登记请求参数、响应字段、可空值、默认排序和失败状态。时间统一使用带时区的约定格式，时间线响应对并列事件排序。列表接口空数据返回空数组；查询未知会话返回约定的错误状态。告警已读状态更新是独立写操作，页面和返回结果均应反映更新是否成功。

协议方案变更时，比较两套实现能否输出同一事件格式，以及认证失败、查询结果状态等字段是否齐全。把字段缺失和覆盖范围写入验证记录。

## 八 安全约束与非功能要求

### 安全红线

- 系统只能在课程授权的本机、虚拟机或隔离实验网络中运行。
- 不得把蜜罐端口直接暴露到公共互联网，也不得扫描或测试未授权地址。
- 诱饵数据不得包含真实身份证号、真实手机号、真实口令、真实密钥或可用的内网连接信息。
- 系统不得执行测试端提交的操作系统命令，不得提供文件上传和任意代码执行能力。
- 伪造连接串只能指向本机或隔离网络中的无效地址，不能形成通往真实资产的跳板。
- 认证测试使用虚构账号及测试标识，控制台与导出材料展示脱敏结果。

### 非功能要求

| 类别 | 要求 |
| --- | --- |
| 可用性 | 演示脚本连续执行三次，系统均能完成连接、记录、分析和展示 |
| 响应性 | 普通查询在本机环境中应快速返回，告警和画像在短时间内刷新 |
| 完整性 | 数据库写入失败时记录错误，不得静默丢失关键事件 |
| 可解释性 | 每个标签和分数都能显示触发规则及证据 |
| 可维护性 | 端口、诱饵账号、规则阈值和数据保留时间通过配置文件管理 |
| 可移植性 | 项目能够通过明确步骤在另一台课程实验机上运行 |
| 隐私保护 | 展示和导出默认隐藏完整口令及可能识别个人的信息 |

### 日志与异常

系统应区分业务事件日志和自身运行日志。业务事件写入 attack_log，自身异常写入应用日志。数据库被锁定、写入失败、规则异常和端口占用等情况应显示明确错误，并允许演示人员快速判断是否需要切换到录屏或降级方案。

### 扩充 数据暴露面的检查

| 检查对象 | 核对内容 | 验证材料 |
| --- | --- | --- |
| 诱饵入口 | 仅限本机或授权隔离环境，数据全部虚构 | 启动配置和隔离说明 |
| API 与页面 | 事件详情与告警响应只返回允许展示的字段 | 响应样例和界面截图 |
| 数据导出 | 报告、录像、日志导出内容均做字段审查 | 导出抽样结果 |
| 可选 AI | 查询限定在批准的只读视图或模板 | 允许和拒绝两类用例 |

建议优先用专用合成标签或脱敏标识表达认证样本间的区别，并把异常信息与业务事件分开保存。业务事件失败时，运行日志中保留可用于定位的事件编号与失败阶段。

## 九 演示方案与测试计划

### 现场演示顺序

1. 展示空白或已清理的控制台，说明当前没有测试事件。
2. 使用 MySQL 客户端连接诱饵端口，先以未知用户名触发认证失败，再以诱饵账号进入系统。
3. 执行 SHOW DATABASES、SHOW TABLES 和 DESCRIBE，展示踩点标签。
4. 载入合成批量读取样本，展示对应标签和风险分变化。
5. 载入预设的写操作被拒绝事件，展示规则证据和告警。
6. 回到控制台，展示同一 session_id 的完整时间线、规则证据、画像和告警。
7. 说明查询结果全部为伪造数据，并展示诱饵与真实数据隔离的设计。

### 演示数据准备

- 预置 20 至 50 条 fake_users 记录和足够数量的 fake_orders 记录。
- fake_config 中的密钥和连接串必须无效，并带有明显的测试标识。
- 演示前保留一份干净数据库副本，出现异常时可快速恢复。
- 准备一段完整录屏作为网络、端口或前端故障时的备份。

### 测试矩阵

| 测试 | 操作 | 预期结果 |
| --- | --- | --- |
| 连接测试 | 使用诱饵账号连接 | 生成 connect 和 auth 事件并建立 session_id |
| 失败认证 | 使用未知用户名连接 | 返回失败并累计认证尝试 |
| 踩点测试 | 执行 SHOW 和 information_schema 查询 | 命中 R03 并更新 recon 标签 |

### 数据库专项演示

1. 展示 sessions 与 attack_log 的主外键关系，并尝试插入不存在的 session_id，说明外键能够阻止脏数据。
2. 重复提交同一 event_uuid，说明 UNIQUE 约束保证事件写入幂等。
3. 演示一次事务中的故意失败，确认 sessions、日志、规则命中、告警和画像同时回滚。
4. 查询四个核心视图，指出其中使用的 JOIN、GROUP BY、CTE 或窗口函数。
5. 对两条高频查询执行 EXPLAIN，对比复合索引建立前后的 key、type 和 rows。

### 答辩口径

项目的创新点应表述为场景组合和完整闭环，不应夸大为新的安全算法。合适的表述是：项目把 MySQL 协议诱饵、结构化行为日志、可解释规则、攻击者画像和实时展示整合为一个课程级系统。

项目的限制也应主动说明。规则阈值来源于课程演示数据，不能直接用于生产环境；客户端工具识别可能存在误判；SQLite 适合单机演示，不代表高并发方案；蜜罐只能观察进入诱饵环境的行为。

### 主要风险与预案

| 风险 | 影响 | 预防措施 | 降级方案 |

### 扩充 开发阶段怎样推进

## 项目基线结论

本项目以数据库课程能力为基础，以数据库蜜罐为应用场景。系统通过模拟 MySQL 服务接收授权测试流量，以 sessions 为会话主表，把事件、规则命中、攻击意图、画像和告警写入具有正式约束的关系数据库，再通过核心视图和确定性规则完成分析展示。项目优先完成最小闭环，AI 只作为可关闭的只读查询与解释功能。

后续的 PPT、课程报告、数据库脚本、代码目录、测试用例和答辩讲稿均应使用本文件的术语、范围和数据流。需要改变基线时，先更新本文件，再同步修改其他材料。
