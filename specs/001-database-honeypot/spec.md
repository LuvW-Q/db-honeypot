## 用户场景与测试 *(mandatory)*

### 用户故事 1 - 诱饵数据库对外提供可交互的虚假 MySQL 服务（优先级：P1）

授权测试者使用 MySQL 客户端或脚本连接隔离网络中的诱饵端口，完成基本握手与认证，
执行 SHOW DATABASES、SHOW TABLES、DESCRIBE、SELECT 与 information_schema 查询，
看到结构合理但完全虚构的数据库内容；尝试写入或破坏时得到受控的权限不足响应。

**Why this priority**：诱饵服务是系统产生真实观测数据的唯一入口。没有可连接的诱饵，
后续的捕获、存储、分析、展示全部无法演示，因此这是最小闭环的第一环。

**Independent Test**：在隔离环境中用 MySQL 客户端连接诱饵端口，依次执行元数据查询与
SELECT，确认返回结构正确且全部为伪造数据；执行 UPDATE/DELETE/DROP 确认收到权限不足
响应且服务不中断。

**Acceptance Scenarios**：

1. **Given** 诱饵服务已在配置端口启动，**When** 授权客户端发起连接，**Then** 服务完成
   MySQL 基本握手并允许继续交互，且客户端侧不出现协议级崩溃。
2. **Given** 客户端使用预置诱饵账号，**When** 提交测试凭据，**Then** 认证成功并允许执行
   演示所需查询；使用未知虚构账号时认证失败，但连接与失败结果均被记录。
3. **Given** 客户端已通过认证，**When** 执行 SHOW DATABASES、SHOW TABLES、DESCRIBE、
   SELECT 或 information_schema 查询，**Then** 返回预设的伪造库表结构或伪造记录，
   查询内容不与任何真实业务数据相关。
4. **Given** 客户端提交 UPDATE、DELETE、DROP、TRUNCATE 或 INSERT，**When** 服务处理该
   语句，**Then** 完整记录该语句并返回权限不足或模拟错误，且诱饵服务保持可用。
5. **Given** 客户端发送无法识别的语句或畸形报文，**When** 服务无法正常处理，**Then**
   返回受控错误并记录该事件，不执行任何操作系统命令或文件操作。

### 用户故事 2 - 连接与 SQL 行为被结构化捕获并可在会话内追溯（优先级：P1）

系统为每次连接生成唯一会话编号，把连接、认证、查询与断开转换为带唯一事件编号的标准
事件，同一会话的事件可按发生顺序还原；检索人员能从会话出发定位到每一条原始 SQL 与
其处理结果。

**Why this priority**：结构化事件是存储、分析、画像和展示的共同数据基础。缺少统一的
事件模型与会话关联，数据库设计的主外键关系和全部下游分析都失去依据。

**Independent Test**：制造一次包含连接、认证失败、认证成功、多次查询与断开的完整交互，
按会话编号查询事件列表，确认事件类型、来源地址、时间、处理结果与顺序均正确，且
连接事件与认证事件分别记录。

**Acceptance Scenarios**：

1. **Given** 客户端首次连接诱饵服务，**When** 连接建立，**Then** 系统生成全局唯一
   session_id，并写入一条 connect 事件，记录来源地址、连接时间与客户端特征。
2. **Given** 同一次连接内发生认证与多条 SQL，**When** 查询该会话的全部事件，**Then**
   事件按事件时间升序排列，时间戳相同的并列事件按持久化事件序号稳定排序。
3. **Given** 一条查询事件已被捕获，**When** 查看该事件，**Then** 可看到原始 SQL、
   标准化 SQL、返回行数、模拟响应耗时与处理状态（成功、失败、拒绝、错误）。
4. **Given** 会话结束，**When** 查看该会话，**Then** 会话的结束时间、状态、事件计数与
   最高风险分与其中事件一致，且结束时间不早于开始时间。

### 用户故事 3 - 原始事件写入具备完整关系约束、事务与幂等保障（优先级：P1）

存储层把会话、日志、规则命中、告警与画像的写入放在同一个事务中完成；重复提交同一
采集事件时系统返回已有事件、不重复计数；任何一步失败时相关表恢复到写入前状态。

**Why this priority**：数据库课程项目的核心能力体现在真实的关系设计、事务与约束上。
只有键、外键、唯一约束与事务正确，系统结论才可信，数据库专项演示才有材料。

**Independent Test**：对同一 event_uuid 连续提交两次，确认只产生一条日志且计数不变；
故意让画像写入失败，确认会话、日志、命中与告警均未残留；尝试写入不存在的 session_id，
确认被外键拒绝。

**Acceptance Scenarios**：

1. **Given** 一条采集事件携带已有 event_uuid，**When** 存储层再次处理该事件，**Then**
   不新增事件记录，返回已有事件编号，相关计数与风险贡献保持不变。
2. **Given** 一次事件处理同时涉及会话更新、日志写入、规则命中、告警生成与画像更新，
   **When** 其中任一步失败，**Then** 整个事务回滚，数据库状态与本事务开始前一致。
3. **Given** 一条日志试图引用不存在的会话编号，**When** 执行写入，**Then** 外键约束
   阻止该写入并返回明确错误。
4. **Given** 分数、计数或状态字段被写入非法值，**When** 执行写入，**Then** 检查约束
   阻止写入并返回可定位字段的错误信息。
5. **Given** 演示需要清空业务数据，**When** 执行重置，**Then** 按外键依赖顺序清理规则
   命中、告警、日志、会话与画像，规则种子保留；中途异常时整体回滚。

### 用户故事 4 - 确定性规则识别意图并提供可解释的风险画像（优先级：P1）

规则引擎依据启用的检测规则识别扫描、爆破、踩点、拖库四类意图，并单独标记破坏性操作；
系统按来源地址聚合攻击者画像，计算 0 到 100 的风险分与风险等级，每个意图标签和分数
都能追溯到具体规则、事件与证据摘要。

**Why this priority**：意图识别与画像是项目“分析”能力的核心，也是控制台告警与展示的
数据来源。没有可解释的规则与评分，系统只是日志采集器。

**Independent Test**：导入固定合成样本（覆盖五条规则各自的正例与反例、阈值边界、重复
处理、封顶、停用规则与版本切换），核对命中规则编号、意图记录、风险分、风险等级与证据
摘要是否符合预期，且可从画像逐级回溯到会话、事件与规则版本。

**Acceptance Scenarios**：

1. **Given** 60 秒内来自同一来源的连接不少于 10 次且均无有效 SQL，**When** 触发扫描
   规则，**Then** 系统记录 R01 命中、更新扫描意图并计入对应权重分。
2. **Given** 5 分钟内同一来源认证尝试不少于 8 次且凭据组合不少于 5 组，**When** 触发
   爆破规则，**Then** 系统记录 R02 命中、更新爆破意图并计入对应权重分。
3. **Given** 出现 SHOW、DESCRIBE 或 information_schema 查询，**When** 触发踩点规则，
   **Then** 系统记录 R03 命中，证据摘要说明触发语句类型，并更新踩点意图。
4. **Given** 出现连续 SELECT 或会话累计返回行数超过阈值，**When** 触发拖库规则，
   **Then** 系统记录 R04 命中并更新拖库意图。
5. **Given** 出现 DROP、TRUNCATE、DELETE、UPDATE 或 INSERT，**When** 触发破坏性规则，
   **Then** 系统记录 R05 命中并单独标记破坏性意图。
6. **Given** 同一来源同时命中多条规则，**When** 计算画像，**Then** 风险分为启用规则
   权重的确定性聚合且不超过 100，风险等级落在低、中、高、严重四个区间之一。
7. **Given** 规则被停用或版本切换，**When** 再次分析，**Then** 停用规则不参与新命中，
   历史命中保留当时实际采用的规则版本与权重快照。
8. **Given** 用户查看攻击者画像，**When** 展开任一意图，**Then** 可看到触发规则编号、
   命中时间与证据摘要，主要意图按分数、最近时间与危害程度稳定排序。

### 用户故事 5 - 会话时间线与攻击者详情可逐条还原攻击行为链（优先级：P2）

观察者在控制台按会话编号查看完整事件时间线（认证与 SQL 交错按时间排序），并查看该
会话的规则命中、证据摘要与风险分；从攻击者详情可进入其名下各会话并核对首末时间、
连接数、认证尝试数与查询数。

**Why this priority**：可追溯性是验收标准 A03 的直接要求，也是答辩现场演示的主线；
它把分散的数据表转化为可讲述的攻击行为链。

**Independent Test**：选定包含认证失败、认证成功与多次查询的会话，对照客户端操作时间
核对控制台时间线顺序与内容，确认展示的规则证据与数据库规则命中一致，且口令字段已脱敏。

**Acceptance Scenarios**：

1. **Given** 一个已有事件的会话，**When** 观察者打开该会话时间线，**Then** 按时间顺序
   展示认证与 SQL 事件，并列事件顺序稳定，且每条事件显示处理结果。
2. **Given** 会话中存在规则命中，**When** 查看命中详情，**Then** 显示规则编号、规则名称、
   命中时间与证据摘要，且可从命中定位到原始事件。
3. **Given** 同一来源建立多个会话，**When** 查看该来源的画像，**Then** 连接数、认证尝试数、
   查询数、首次出现时间与最近出现时间与该来源全部会话一致。
4. **Given** 会话或事件包含认证凭据，**When** 页面展示与导出，**Then** 完整口令从不出现，
   仅显示脱敏标识或测试标识。

### 用户故事 6 - 告警生成、筛选与已读处置（优先级：P2）

当爆破、拖库或破坏性操作等规则命中达到条件时，系统生成带证据关联的告警；观察者按
类型、时间、等级与已读状态筛选告警，并把告警标记为已读。

**Why this priority**：告警是验收标准 A06 的直接要求，也是控制台第四页面的数据来源，
使系统从“记录”升级为“提示”。

**Independent Test**：用合成样本分别触发爆破、拖库与破坏性告警，核对告警数量、类型、
等级与证据关联；按各筛选条件查询确认结果与数据库一致；更新已读状态后重新查询确认状态
生效且为独立写操作。

**Acceptance Scenarios**：

1. **Given** 爆破规则命中达到条件，**When** 分析完成，**Then** 生成一条关联该会话与
   攻击者的告警，包含类型、等级、触发规则与创建时间。
2. **Given** 拖库或破坏性操作命中达到条件，**When** 分析完成，**Then** 生成对应类型告警，
   并可查询到其证据编号或可定位的命中记录。
3. **Given** 已存在多条告警，**When** 按类型、时间范围、等级或已读状态筛选，**Then**
   返回结果与数据库查询一致，空结果返回空数组而非错误。
4. **Given** 某条告警未被读过，**When** 观察者将其标记为已读，**Then** 该写操作成功并
   在页面与返回结果中体现更新是否成功。
5. **Given** 同一触发条件在短时间内重复出现，**When** 告警去重键匹配已有告警，**Then**
   不产生无法区分的重复告警，且重放测试结果稳定。

### 用户故事 7 - 四页核心控制台提供答辩所需的完整展示（优先级：P2）

观察者在控制台首页查看连接数、查询数、告警数与高风险攻击者数；在攻击者列表按分页浏览
来源、首末时间、意图标签与风险分；在攻击者详情查看会话摘要与时间线；在告警列表筛选并
处置告警。四个页面视觉统一、层级清楚，演示时一眼能看懂。

**Why this priority**：控制台是全部数据能力的最终呈现，也是验收标准 A05、A08 与现场
演示的载体；页面范围固定为四页，避免工期与复杂度失控。

**Independent Test**：在预置数据与空数据两种状态下逐一打开四个页面，核对数字与数据库
聚合结果一致、排序稳定、空态友好、无明文口令，并在本机演示环境中记录页面刷新耗时。

**Acceptance Scenarios**：

1. **Given** 数据库中存在若干会话与告警，**When** 打开首页概览，**Then** 显示连接数、
   查询数、告警数与高风险攻击者数，且与数据库聚合结果一致。
2. **Given** 存在多个来源画像，**When** 浏览攻击者列表，**Then** 分页展示来源地址、
   首次与最近出现时间、主要意图标签与风险分，排序稳定且支持翻页。
3. **Given** 选定某个来源，**When** 打开攻击者详情，**Then** 展示画像统计、该来源的
   会话摘要与进入时间线的入口。
4. **Given** 数据库为空，**When** 打开任一页面，**Then** 显示明确空态或空数组，不报错。
5. **Given** 四页面均使用核心分析视图，**When** 对照页面数字与视图查询结果，**Then**
   两者完全一致，且每个视图都有一条可直接演示的查询。

### 用户故事 8 - 规则配置与版本管理支撑可解释调整（优先级：P3）

系统管理员查看规则说明、当前阈值、权重、版本与启用状态，并按需停用规则或调整阈值；
调整后新的分析使用新版本，历史证据保留当时的版本快照。

**Why this priority**：规则可配置是总纲对检测规则表的明确要求，也是答辩说明“阈值可
修订且可追溯”的依据；但它依赖规则引擎与画像已可用。

**Independent Test**：停用一条规则后确认其不再产生新命中且总分变化符合预期；修改阈值
产生新版本后确认新事件按新版本判定、旧命中仍显示旧版本与旧权重。

**Acceptance Scenarios**：

1. **Given** 系统已初始化规则种子，**When** 查看规则列表，**Then** 能看到规则编码、名称、
   类型、意图、阈值参数、权重、版本与启用状态。
2. **Given** 管理员停用某条规则，**When** 新事件被分析，**Then** 该规则不参与命中与评分。
3. **Given** 管理员调整阈值并产生新版本，**When** 新事件命中该规则，**Then** 命中记录
   保存新版本号与新权重快照，历史命中仍保留旧版本快照。

---

### 用户故事 9 - 固定合成样本与模拟器支撑可重复验证（优先级：P3）

项目提供授权模拟脚本与固定合成样本（连接、认证、查询、批量读取、被拒绝写操作），
在空库状态下导入后可稳定复现预期标签、评分与告警，用于测试矩阵与答辩兜底演示。

**Why this priority**：合成样本让检测规则在不受网络与客户端差异影响下可重复验证，是
测试计划和“演示可复现”验收的关键支撑。

**Independent Test**：从空库导入三条固定合成事件（连接、认证、查看表列表），确认同一
会话产生三条有序日志且仅查看表列表命中 R03；再导入批量读取与被拒绝写操作样本，核对
R04、R05 与告警。

**Acceptance Scenarios**：

1. **Given** 空数据库，**When** 导入三条固定合成事件，**Then** 同一会话内三条日志按序
   可查，且仅查看表列表事件命中 R03。
2. **Given** 预设批量读取样本，**When** 导入并分析，**Then** 命中 R04 并产生预期分数与
   告警，重复导入结果稳定。
3. **Given** 预设被拒绝写操作样本，**When** 导入并分析，**Then** 命中 R05，证据保留且
   可回溯到事件。
4. **Given** 模拟器需要生成测试流量，**When** 运行脚本，**Then** 仅连接配置中声明为
   授权的隔离目标，不扫描任何未授权地址。

### 用户故事 10 - AI 只读辅助查询与解释（可选增强，可整体关闭）（优先级：P3）

观察者用自然语言提出只读问题，系统把问题映射到预设只读查询模板或解释已有视图与规则
证据；AI 输出明确标记为辅助解释，不参与核心检测与风险判定，功能不可用时系统其余部分
完整运行。

**Why this priority**：总纲将 AI 定位为演示增强，必须在最小闭环稳定后再增加，且必须
可关闭，因此优先级最低。

**Independent Test**：在 AI 功能开启时验证允许的只读查询可用、越权与写操作被拒绝；
在 AI 功能关闭或不可用时验证概览、画像、告警、时间线与演示流程不受影响。

**Acceptance Scenarios**：

1. **Given** AI 功能开启，**When** 观察者提出可映射到批准视图的问题，**Then** 返回基于
   只读查询模板的结果，并标记为辅助解释。
2. **Given** AI 被要求生成任意 SQL 或修改数据，**When** 提交请求，**Then** 请求被拒绝，
   不执行任何非 SELECT 语句。
3. **Given** AI 功能关闭或不可用，**When** 使用系统其他功能，**Then** 检测、画像、告警
   与控制台均正常运行。

### 边界情况

- 同一 event_uuid 被并发或重复提交：只能产生一条日志，返回已有事件编号，计数与风险贡献不变。
- 写入引用不存在的 session_id 或 rule_id：外键拒绝，错误信息可定位。
- 会话哈希/编号冲突：系统必须重新生成或拒绝，不得覆盖已有会话。
- 时间线中多条事件时间戳完全相同：按持久化事件序号稳定排序，重复查询顺序一致。
- 未知 session_id 或未知攻击者查询：返回约定的“未找到”错误状态，而非空页面或服务器错误。
- 风险分超过 100：按封顶策略计为 100，且每分仍可追溯到规则命中。
- 规则全部停用：风险分为 0，不产生标签与告警，页面正常显示空态。
- 同一规则重复分析同一事件：不得重复累计分值或证据计数。
- 超大或畸形 SQL、超长用户名、非常规编码：按上限截断或拒绝并记录，不导致存储或查询失控。
- 认证失败与认证成功交替出现：分别记录，失败尝试同样计入认证尝试统计。
- 诱饵端口被占用、数据库被锁定或写入失败：显示明确错误，业务事件不静默丢失，运行日志保留定位信息。
- 演示重置中途异常：按事务回滚到重置前状态，规则种子与配置不被破坏。
- 告警已读更新与页面并发：更新结果以数据库实际状态为准，失败时页面明确提示。
- 空数据状态：首页、列表、详情、告警页均显示空态或空数组，不出现异常。
- 导出或页面展示包含认证字段：完整口令必须始终被脱敏或剔除。

## 需求 *(mandatory)*

### 功能需求

#### 诱饵服务（DE）

- **FR-001**：系统必须监听配置指定的端口，接受授权客户端的 MySQL 基本握手。
- **FR-002**：系统必须支持可配置的诱饵账号策略；预置账号的认证成功与未知账号的认证
  失败都必须记录为认证事件。
- **FR-003**：系统必须支持 SHOW DATABASES、SHOW TABLES、DESCRIBE、SELECT 以及
  information_schema 查询，并返回预设的伪造结果。
- **FR-004**：系统必须对 UPDATE、DELETE、DROP、TRUNCATE、INSERT 等写操作记录语句并
  返回权限不足或受控错误，不得真实修改任何数据。
- **FR-005**：诱饵内容必须至少包含 users、orders、config 三类表；users 提供伪造账号、
  邮箱、手机号与密码哈希，orders 提供伪造订单，config 提供看似敏感但无效且带明显测试
  标识的连接串与密钥。
- **FR-006**：所有诱饵数据必须可识别为人工生成，不得包含真实个人信息、真实口令、
  真实密钥或可用的内网连接信息；伪造连接串只能指向本机或隔离网络中的无效地址。
- **FR-007**：系统不得执行客户端提交的操作系统命令，不得提供文件上传或任意代码执行能力。
- **FR-008**：对无法识别的语句、协议错误或畸形报文，系统必须返回受控错误并记录事件，
  且保持服务可用。
- **FR-009**：诱饵服务必须仅在授权的本机、虚拟机或隔离实验网络中运行，不得暴露到公共
  互联网，不得扫描或连接未授权地址。
- **FR-010**：诱饵层返回伪造数据、空结果、权限错误或受控延迟时，响应内容必须与虚构
  业务结构一致，且事件记录中保存响应状态。

#### 捕获与会话（CA）

- **FR-011**：系统必须为每次连接生成全局唯一的 session_id，作为会话主键。
- **FR-012**：系统必须把协议交互转换为标准事件，事件至少包含事件编号、事件唯一键、
  会话编号、事件类型、来源地址、发生时间、处理结果与返回行数等字段。
- **FR-013**：标准事件必须覆盖 connect、auth、query、disconnect 等类型；连接成功与认证
  成功必须分别记录。
- **FR-014**：认证事件必须记录使用的用户名、认证结果与可选的合成凭据测试标识；
  查询事件必须记录原始 SQL、标准化 SQL、返回行数与响应耗时。
- **FR-015**：每个采集事件必须携带幂等键（event_uuid），其生成时机、时区与唯一性规则
  必须在事件模型中固定。
- **FR-016**：同一次连接内的所有事件必须共享同一 session_id，以便按会话还原时间线。
- **FR-017**：会话必须记录来源地址、来源端口、目标服务、开始时间、结束时间、状态、
  事件计数与最高风险分；结束时间不得早于开始时间。
- **FR-018**：事件时间必须使用统一时区与统一格式；时间线必须按事件时间升序排列，时间戳
  相同时按持久化事件序号稳定排序。
- **FR-019**：事件写入失败必须在运行日志中保留事件编号、失败阶段与可定位信息，不得
  静默丢失关键事件。
- **FR-020**：系统必须支持按配置的数据保留策略清理课程测试数据；导出前必须删除或遮盖
  口令字段。

#### 存储与数据库设计（ST）

- **FR-021**：系统必须使用关系数据库持久化会话、事件、规则命中、攻击意图、规则、画像、
  告警与诱饵数据；相关实体关系必须以正式主键、外键、唯一约束与检查约束表达。
- **FR-022**：sessions 必须是会话主表，attack_log、rule_hits、alerts 必须通过 session_id
  与 sessions 建立正式外键引用。
- **FR-023**：attack_log 必须通过 event_uuid 建立唯一约束实现事件幂等；重复提交不得新增
  记录，并返回已有事件编号。
- **FR-024**：attacker_intent 必须一行只保存一条攻击者意图，并以“画像编号＋意图类型”
  复合唯一约束保证每名攻击者每种意图只有一条聚合记录。
- **FR-025**：attacker_profile 不得保存多值意图列表（不得使用逗号串或 JSON 数组长期
  存意图）；主要意图必须由分析视图根据意图分数与最近命中时间计算。
- **FR-026**：detection_rules 必须保存规则编码、名称、类型、意图、参数、风险权重、版本
  与启用状态；rule_code 与 rule_version 必须复合唯一。
- **FR-027**：规则的阈值与时间窗口参数必须按单条规则结构保存；参数结构不得用于保存
  多个业务实体。
- **FR-028**：rule_hits 必须记录命中的事件、规则、会话、得分、证据摘要与命中时间，并
  保存命中当时实际采用的规则版本与权重快照。
- **FR-029**：alerts 必须记录会话、攻击者、告警类型、等级、证据关联、去重键、创建时间
  与已读状态。
- **FR-030**：诱饵表必须包含 fake_users、fake_orders 与 fake_config；fake_orders 必须
  关联 fake_users，fake_config 的配置键必须唯一。
- **FR-031**：分数类字段必须限制在 0 到 100；计数类字段必须非负；时间范围、状态与类型
  字段必须使用检查约束限制在允许枚举内。
- **FR-032**：系统必须提供四个核心分析视图：会话风险汇总（v_session_risk_summary）、
  攻击者画像汇总（v_attacker_profile_summary）、每日攻击趋势（v_daily_attack_trend）与
  规则效果统计（v_rule_effectiveness）；视图必须使用 JOIN、聚合、CTE 或窗口函数表达
  对应分析。
- **FR-033**：四个核心视图必须被控制台或答辩查询实际使用，且每个视图必须有一条可直接
  演示的 SELECT 查询。
- **FR-034**：系统必须为高频查询建立复合索引，至少覆盖“按会话重建时间线”“按来源和
  时间范围查询行为”“筛选近期高等级告警”“统计规则命中趋势”四类目标查询。
- **FR-035**：项目必须记录至少两组索引建立前后的查询计划对比（访问类型、使用索引、
  估算行数与实测耗时），用于答辩说明。
- **FR-036**：数据库必须能够从建表、种子数据、视图与索引脚本完整重建，并保持可重置的
  演示库。
- **FR-037**：系统必须提供统一启动入口、依赖说明、初始化、启动、健康检查与关闭顺序的
  运行说明。
- **FR-038**：所有 DDL、迁移脚本、种子数据与索引脚本必须纳入版本控制。

#### 事务与幂等（TX）

- **FR-039**：事件写入事务必须把会话创建或更新、日志写入、规则命中、告警生成与画像更新
  作为一个事务执行，任一步失败时整体回滚。
- **FR-040**：演示重置事务必须按外键依赖顺序清理规则命中、告警、日志、会话与画像，异常
  时回滚到重置前状态，且不得删除规则种子与配置。
- **FR-041**：幂等必须由数据库唯一约束保证，同时调用方必须区分“已存在”与“本次新增”
  两种结果。
- **FR-042**：数据库写入失败、约束冲突、锁定或端口占用等情况必须返回明确错误并记录运行
  日志，禁止静默失败。
- **FR-043**：数据库连接必须启用外键约束；每个业务事务必须显式提交或回滚。

#### 意图识别与风险评分（AN）

- **FR-044**：规则引擎必须只执行启用状态的规则，并输出命中的规则编号、意图类型、得分
  与证据摘要。
- **FR-045**：系统必须内置 5 至 8 条初始规则，且至少覆盖 R01 扫描、R02 爆破、R03 踩点、
  R04 拖库、R05 破坏性操作，其初始条件与建议权重为：R01 为 60 秒内连接不少于 10 次且
  无有效 SQL（权重 10）；R02 为 5 分钟内认证不少于 8 次且凭据组合不少于 5 组（权重 25）；
  R03 为出现 SHOW、DESCRIBE 或 information_schema 查询（权重 15）；R04 为连续 SELECT
  或会话累计返回行数超过阈值（权重 25）；R05 为出现 DROP、TRUNCATE、DELETE、UPDATE 或
  INSERT（权重 35）。
- **FR-046**：规则必须简单、可测试、可解释；规则参数、权重、版本与启用状态必须由数据库
  配置，不得硬编码为不可查的常量。
- **FR-047**：风险分必须是启用规则命中权重的确定性聚合，最高 100 分并采用封顶策略；
  每一分必须能对应 rule_hits 中的规则、事件与证据。
- **FR-048**：风险等级必须为 0 至 29 低风险、30 至 59 中风险、60 至 79 高风险、80 至 100
  严重风险四档。
- **FR-049**：意图记录必须在命中新证据时更新累计可信分、证据计数与最近识别时间；同一
  攻击者必须可以同时拥有多条不同意图记录。
- **FR-050**：主要意图必须由画像视图按分数、最近命中时间与危害程度排序得出，排序在分数
  和时间相同时必须稳定。
- **FR-051**：画像页面必须显示规则编号、命中时间与证据摘要，禁止只给标签而不给触发依据。
- **FR-052**：规则版本切换后，新命中保存新版本与新权重快照，历史命中保留旧版本快照；
  重新计算历史数据时必须明确重算范围、规则版本与结果口径。
- **FR-053**：AI 不得参与风险分计算、规则命中修改与最终风险等级判定；AI 功能关闭或
  不可用时检测、画像、告警与展示必须完整运行。
- **FR-054**：系统必须支持规则的启用、停用、阈值调整、权重调整与版本管理，不开发复杂
  规则语言。

#### 告警（AL）

- **FR-055**：爆破、拖库或破坏性操作等规则命中达到条件时，系统必须生成告警记录。
- **FR-056**：告警必须可通过类型、时间、等级与已读状态筛选，空结果返回空数组。
- **FR-057**：告警必须关联会话与攻击者，并保留可查询的证据编号或可定位的命中记录。
- **FR-058**：告警已读状态更新必须是独立写操作，页面与返回结果必须反映更新是否成功。
- **FR-059**：告警去重键必须与触发条件匹配，并为重复触发与重放准备稳定测试。
- **FR-060**：告警必须包含等级、类型、创建时间、触发规则、处置或已读状态等可展示字段。

#### 展示与控制台（UI）

- **FR-061**：控制台必须提供四个核心页面：首页概览、攻击者列表、攻击者详情与告警列表。
- **FR-062**：首页概览必须显示连接数、查询数、告警数与高风险攻击者数，并与数据库聚合
  结果一致。
- **FR-063**：攻击者列表必须分页展示来源地址、首次与最近出现时间、主要意图标签与风险分。
- **FR-064**：攻击者详情必须展示画像统计、会话摘要、进入会话时间线的入口与规则证据。
- **FR-065**：会话时间线必须按 session_id 展示认证与 SQL 事件的先后顺序与处理结果。
- **FR-066**：告警列表必须支持按类型、时间、等级与已读状态筛选并支持标记已读。
- **FR-067**：四个页面必须使用统一配色、清楚层级与适量图表，以答辩现场可读为首要目标；
  不实现复杂权限系统、主题系统或大屏编辑器。
- **FR-068**：控制台必须以只读查询为主；观察者默认只读，页面不得显示完整口令或可识别
  个人的敏感信息。
- **FR-069**：未知会话或未知攻击者必须返回约定的未找到错误状态；列表空数据必须返回空
  数组或明确空态。
- **FR-070**：控制台必须优先查询核心视图，详情页再读取原始日志与规则证据，展示结果必须
  与数据库查询一致。

#### 配置、运行与可维护性（OP）

- **FR-071**：端口、诱饵账号、规则阈值、数据保留时间与授权目标地址必须通过配置文件管理。
- **FR-072**：开发库、自动化测试库与现场演示库必须可以分别配置，互不污染。
- **FR-073**：系统运行日志必须与业务事件日志分开保存；业务事件写入 attack_log，自身异常
  写入应用日志。
- **FR-074**：数据库被锁定、写入失败、规则异常或端口占用时，系统必须显示明确错误，便于
  演示人员判断是否切换录屏或降级方案。
- **FR-075**：演示前必须支持保留一份干净数据库副本并在异常时快速恢复。
- **FR-076**：项目必须能够通过明确步骤在另一台课程实验机上运行。
- **FR-077**：项目必须提供授权模拟脚本，仅生成测试流量并仅连接配置声明的授权目标。
- **FR-078**：配置与运行说明必须写明初始化、启动、健康检查、关闭顺序、重置方法与常见
  故障处理。

#### 安全、隐私与演示验收（SF）

- **FR-079**：系统只能在授权的本机、虚拟机或隔离实验网络中运行；不得把蜜罐端口暴露到
  公共互联网。
- **FR-080**：系统不得连接真实业务数据库，不得使用真实敏感数据，不得主动反制、实施漏洞
  利用或投递恶意代码。
- **FR-081**：认证测试必须使用虚构账号及测试标识；控制台与导出材料必须展示脱敏结果。
- **FR-082**：事件详情与告警响应必须只返回允许展示的字段；导出内容必须经过字段审查。
- **FR-083**：蜜罐采集到的 SQL、用户名、口令与客户端信息必须视为不可信数据，只存储、
  不执行；任何重放必须在隔离环境进行。
- **FR-084**：系统必须提供合成事件样本与模拟器，支持在不依赖真实客户端差异的情况下
  稳定触发规则、画像与告警。
- **FR-085**：演示数据必须预置 20 至 50 条 fake_users 以及足够数量的 fake_orders；
  fake_config 的密钥与连接串必须无效且带测试标识。
- **FR-086**：演示脚本必须支持连续执行三次，每次均能完成连接、记录、分析与展示。
- **FR-087**：系统必须提供覆盖连接、失败认证、踩点、拖库、破坏、画像、界面与恢复的测试
  矩阵，并提供数据库专项演示步骤（外键拦截、幂等、事务回滚、四视图、查询计划对比）。
- **FR-088**：每次演示重置后必须先核对规则种子仍在、历史会话已清空，再开始下一轮；需
  准备录屏作为环境故障时的备份。
- **FR-089**：AI 辅助功能必须使用只读账户、只允许 SELECT、限定在批准的视图或预设模板内，
  不得执行任意生成的 SQL；其输出必须标记为辅助解释。

### 关键实体 *(涉及数据时必填)*

- **sessions（会话）**：会话主表；session_id 主键，记录来源地址、来源端口、目标服务、
  开始/结束时间、会话状态、事件计数与最高风险分；结束时间不得早于开始时间，计数非负。
  一个会话对应多条 attack_log、rule_hits 与 alerts。
- **attack_log（攻击日志）**：标准事件记录；event_id 自增主键、event_uuid 唯一幂等键、
  session_id 外键、事件类型、来源地址、用户名、合成凭据测试标识、原始与标准化 SQL、
  事件时间、返回行数、响应耗时与处理状态；与 sessions 为多对一关系。
- **rule_hits（规则命中）**：一次命中记录；关联事件、规则与会话，保存得分、证据摘要、
  命中时间与规则版本/权重快照；一条事件可对应多条命中。
- **attacker_profile（攻击者画像）**：按来源地址聚合；来源地址唯一，记录首末出现时间、
  累计连接数、认证尝试数、查询数、风险分与证据摘要；一个画像对应多条会话、意图与告警。
- **attacker_intent（攻击意图）**：一行一条意图；关联画像，记录意图类型、累计可信分、
  证据计数与首末识别时间；“画像编号＋意图类型”唯一。
- **detection_rules（检测规则）**：规则配置；规则编码、名称、类型、目标意图、参数、风险
  权重、版本与启用状态；规则编码与版本复合唯一。
- **alerts（告警）**：告警记录；关联会话、攻击者、触发规则与证据，记录类型、等级、去重键、
  创建时间与已读状态。
- **fake_users / fake_orders / fake_config（诱饵数据）**：对外展示的完全虚构数据；
  fake_orders 关联 fake_users，fake_config 配置键唯一；所有内容必须明显为人工生成。
- **核心分析视图**：会话风险汇总、攻击者画像汇总、每日攻击趋势与规则效果统计四个只读
  数据产品，供控制台与答辩查询使用。
- **实体关系总览**：sessions 为行为事实的中心，attack_log 与 alerts 经由 session_id
  归集；rule_hits 串联事件、规则与证据；attacker_profile 与 attacker_intent 提供按来源
  聚合；诱饵表仅用于对外展示，不与观测数据混存。

## 成功标准 *(mandatory)*

### 可度量结果

- **SC-001**：授权客户端能够连接诱饵端口并完成握手，连续三次尝试均成功（对应验收 A01）。
- **SC-002**：一次完整交互产生的连接、认证与 SQL 事件全部写入数据库，关键字段无缺失，
  日志完整率 100%（对应 A02）。
- **SC-003**：任选一次会话，观察者可在控制台按会话编号还原其事件顺序，时间线与数据库
  查询结果逐条一致（对应 A03）。
- **SC-004**：五条初始规则各至少有一个固定样本可稳定触发对应意图标签，重复执行结果
  一致（对应 A04）。
- **SC-005**：同一来源多次会话后，画像的连接数、查询数、首末时间与风险分与原始数据聚合
  结果完全一致（对应 A05）。
- **SC-006**：爆破、拖库与破坏性操作样本均能生成告警，告警到证据的追溯路径可查询
  （对应 A06）。
- **SC-007**：所有展示与导出数据均为伪造或脱敏数据，抽查 100% 不含真实个人信息、真实
  口令与可用内网信息（对应 A07）。
- **SC-008**：按演示脚本连续执行三次，每轮结果与预期一致，且无人工修补数据步骤
  （对应 A08）。
- **SC-009**：控制台四个核心页面在预置数据与空数据两种状态下均可用，页面数字与视图
  查询结果一致。
- **SC-010**：四个核心视图均被页面或答辩查询实际使用，每个视图至少有一条可直接运行的
  演示查询。
- **SC-011**：重复提交同一事件 10 次后，日志数、计数与风险贡献与提交 1 次相同。
- **SC-012**：在任一写事务中注入失败后，相关五类数据（会话、日志、命中、告警、画像）
  与事务前完全一致，且原事件可重试成功。
- **SC-013**：至少两组高频查询在建立复合索引后查询计划发生变化，记录访问类型、使用
  索引、估算行数与实测耗时。
- **SC-014**：本机演示环境下，普通页面查询与画像刷新可在可接受时间内完成，现场操作后
  控制台及时更新。
- **SC-015**：项目可从建表、种子、视图与索引脚本在另一台实验机完整重建并复现演示。

### 分阶段验收

- **样本闭环**：从空库导入三条固定合成事件（连接、认证、查看表列表）后，同一会话有
  三条有序日志，且只有查看表列表事件命中 R03；以 SQL 查询、规则证据与页面截图作为现场
  证据。
- **诱饵闭环**：一次授权的本地客户端交互后，客户端收到虚假表列表，后台出现对应的新
  会话与事件；以客户端结果、会话编号与控制台时间线作为现场证据。
- **课程交付**：固定合成样本加本地交互后，核心规则、视图、事务、约束与四个页面均可
  单独核验；以测试矩阵、查询计划与复现记录作为现场证据。
- 样本闭环与诱饵闭环必须分别记录，样本闭环证明模块已接通，诱饵闭环另外证明事件确由
  本地交互自动产生。

## 假设

- 项目在隔离的本机、虚拟机或课程实验网络内运行，默认不暴露到公网，演示数据规模为几千
  至几万条，不进行高并发压力测试。
- 团队按课程小组规模运作，页面数量固定为四个核心页面，不实现复杂权限、主题或大屏编辑。
- 诱饵服务与日志存储的具体技术选型按总纲在规划阶段确定；本规格只规定数据含义、行为与
  验收结果，不锁定具体实现。
- 单个来源地址作为画像聚合键，能够代表一次授权测试的身份范围；不处理 NAT 后多主体等
  复杂归因问题。
- 五条初始规则的阈值来自课程演示数据，不代表生产安全基线；阈值可在保留依据与测试样例
  的前提下调整。
- 认证成功依赖预置的虚构诱饵账号与测试凭据；不使用任何真实系统账号。
- AI 功能为选做增强，其接口不可用或关闭时不影响最小闭环与现场演示。
- 演示前会保留干净数据库副本与录屏，作为端口、网络或前端故障的兜底。

## 术语与口径

- **蜜罐**：为吸引和观察攻击行为而设置的诱饵系统。
- **诱饵数据库**：对外表现为 MySQL 服务但只提供伪造数据的模块。
- **事件**：一次连接、认证、查询、响应或断开产生的结构化记录；本规格中观测事件即
  attack_log 中的记录。
- **会话**：由 session_id 标识的一次完整连接过程。
- **攻击者画像**：按来源地址聚合的时间、次数、意图、风险与证据摘要。
- **意图标签**：扫描、爆破、踩点、拖库或破坏性操作等分类结果。
- **规则命中**：某条事件或一组统计结果满足特定版本规则。
- **风险分**：依据连接频率、攻击语句、数据访问等规则命中计算的 0 到 100 分；本规格中
  会话风险分以会话为统计范围，来源画像风险分以来源及约定统计范围聚合。
- **风险等级**：0 至 29 低、30 至 59 中、60 至 79 高、80 至 100 严重。
- **告警**：满足指定条件后生成的独立可查询记录。
- **最小闭环**：连接、捕获、存储、分析、展示与演示全部可用的最低版本。

## 依赖与约束

- **数据模型设计原则**：原始事件、会话、攻击意图、检测规则与聚合画像必须分开保存，
  不得把可查询实体长期放入 TEXT 或 JSON 列表；约束、事务、索引与视图必须服务于可演示
  的业务场景，不得为数量堆叠数据库对象。
- **数据生命周期**：系统必须覆盖“事件生成→事务写入→规则分析→展示→清理保留”五个
  阶段，各阶段职责分离：捕获只生成标准事件，存储只负责持久化，分析只读取事件并产出
  派生结果，展示只做只读查询，清理按保留策略执行且导出前脱敏。
- 数据库课程能力必须通过真实结构与查询体现：会话使用正式主外键，意图按行保存，规则由
  数据库配置，画像与统计使用视图、聚合与窗口函数生成。
- 展示层只读查询为主；唯一的写操作是告警已读状态更新与规则配置管理。
- 安全红线优先级高于功能完整性：一旦安全边界与演示需求冲突，必须先满足安全约束。
- 项目基线变更必须先更新总纲，再同步修改本规格与后续计划、任务与测试材料；变更记录
  必须写明旧方案、新方案、受影响的字段或接口、验证方式与确认状态。
- **降级路线**：若协议模拟无法在规定时间内稳定完成握手，项目必须切换为隔离网络中的
  真实 MySQL 实例，导入伪造数据，并通过 general_log 或审计机制记录操作；降级后必须
  保留相同的日志表、画像表、规则与控制台，仅替换诱饵层实现。
- **协议方案变更验证**：协议实现方案变更时，必须比较两套实现能否输出同一事件格式，
  以及认证失败、查询结果状态等字段是否齐全，并把字段缺失与覆盖范围写入验证记录。
- **风险与降级预案**：协议模拟不稳定时固定客户端版本并只实现最少语句；日志字段不完整
  时先冻结事件模型与 session_id 再写协议逻辑；规则误判时每条规则准备独立测试样例并以
  固定脚本和明确阈值演示；前端工期超出时先完成服务端模板页面与基础表格；现场环境故障
  时以录屏、截图与干净数据库副本兜底；安全边界不清时停止外部连接，仅在本机回环地址
  演示。
- **完成定义**：项目只有在代码能够运行、数据库能够查询、规则能够解释、页面能够展示、
  演示能够复现、文档能够对应且安全约束得到满足时才算完成；单独完成页面、脚本或报告
  不构成项目完成。
- **最终交付物**：源代码、数据库建表与初始化脚本、配置、测试材料、运行说明属于产品
  交付并纳入本规格验收；课程报告与汇报材料（14 页选题 PPT、最终答辩 PPT、演示脚本、
  录屏、截图、分工记录）属于项目文档交付，必须与本规格所列功能、术语与统计口径一致，
  但不作为功能需求的验收对象。
- 总纲中的开题页码、时间节点与小组分工属于 2026 年 9 月的历史安排，不进入功能规格；
  如与当前实现冲突，以总纲的基线内容与最新确认版本为准。
