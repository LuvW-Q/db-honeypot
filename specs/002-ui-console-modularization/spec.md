# 功能规格：深色赛博终端控制台重制与五模块目录解耦

**Feature Branch**: `002-ui-console-modularization`

**Created**: 2026-11-25

**Status**: Draft

**Input**: 用户描述："这个 spec 解决两个问题：1. 实现新设计的 UI 原型，注意做实际部署测试，
尽量做到视觉上的一致性（原型目录 `ux/stitch_database_honeypot_analytics_console/`）；
2. 解耦模块，按照给定图片的这五个模块，尽量剥离并放在不同文件夹下。" 图片给出五行
"模块 → 必须交付的验收证据" 对照，见附录 A。

**规格定位与基线**：本规格是 001 的**增量规格**，不改变业务能力、数据口径与安全红线，
只做两件事——**替换控制台呈现层**、**重组交付结构（五模块目录 + 证据自包含）**。
001 的 FR-001 至 FR-089、SC-001 至 SC-015 与验收 A01 至 A08 继续有效。两者冲突时：
数据含义、口径、安全约束以 001 为准；视觉呈现与目录结构以本规格为准。
功能需求编号从 **FR-090** 起、成功标准从 **SC-016** 起，避免与 001 编号冲突。

**两个目标（不合并验收）**：

- **目标一（视觉交付）**：四页控制台按新原型重制，经真实部署路径上线，并有可复核的
  视觉一致性证据。
- **目标二（结构交付）**：五个模块剥离为独立目录，各自拥有代码、契约说明与可复现的
  验收证据，模块间无隐式依赖。

## 用户场景与测试 *(mandatory)*

### 用户故事 1 - 四页控制台按新原型呈现，视觉与原型逐区域一致（优先级：P1）

观察者打开深色赛博终端风格的控制台：左侧固定导航、顶部状态栏、首页四张指标卡与趋势/
分布图、攻击者列表与详情页的画像证据链、告警流卡片，视觉密度、配色、字体层级与原型
一致。答辩投影时页面在 1440×900 与 1920×1080 两档都清晰、不拥挤、不塌陷。

**Why this priority**：用户明确要求"实现新设计的 UI 原型，尽量做到视觉上的一致性"。
原型是本次交付的视觉契约，四页是评审与答辩的第一印象；没有一致的呈现，其余数据能力
无法被看见。

**Independent Test**：在固定种子数据、固定视口下打开四页，按附录 C 的区域清单逐项
对照原型截图；色板、字阶、圆角、间距按令牌集抽查；确认无横向滚动与元素重叠。

**Acceptance Scenarios**：

1. **Given** 部署环境已启动且种子数据固定，**When** 在 1440×900 打开首页概览，
   **Then** 侧栏、页头、四张 KPI 卡、每日趋势图、规则命中分布、TOP5 榜单按原型顺序与
   比例出现，页面无横向滚动。
2. **Given** 原型截图与实现页面，**When** 按附录 C 逐区域对照，**Then** 每个区域标记
   为"一致"或登记差异理由，一致项占比不低于 95%，差异仅限于真实数据值、字体回退度量
   与附录 B 已裁定的控件调整。
3. **Given** 深色主题页面，**When** 检查颜色、字号、圆角、间距取值，**Then** 全部来自
   DESIGN.md 令牌集，未出现令牌外取值；四级严重度在四页使用同一组语义色。
4. **Given** 攻击者详情页，**When** 打开，**Then** 画像卡、意图与规则证据链、关联会话
   表、会话时间线、底部操作条齐全且层级与原型一致；时间线按时间升序、事件类型有独立
   图标、SQL 以三层结构呈现、口令已脱敏。
5. **Given** 超长 SQL、超长实体标签或大量意图徽标，**When** 页面渲染，**Then** 内容
   换行或容器内滚动，栅格不被撑破，操作按钮仍可点击。
6. **Given** 1024px 与 1920px 两种宽度，**When** 浏览四页，**Then** 布局按原型对应档位
   重排，元素不重叠、关键列不被裁切。

### 用户故事 2 - 控制台经真实部署路径可用并通过实际部署测试（优先级：P1）

评审在自己机器上按文档执行部署流程，用单一地址打开完整控制台；构建产物由服务统一托管，
不是开发服务器；页面在真实浏览器中无报错、无失败请求、无外网依赖，断网也能正常显示。

**Why this priority**：用户明确要求"注意做实际部署测试"。只在开发模式可用的界面不能
作为交付证据，部署失败会让视觉一致性与全部演示无意义。

**Independent Test**：从干净环境执行部署验证流程一条命令，得到健康检查通过、四页可访问、
四页截图与控制台检查报告；断网后重新打开四页确认无塌陷。

**Acceptance Scenarios**：

1. **Given** 干净仓库与可用数据库，**When** 执行部署验证流程，**Then** 依次完成数据库
   准备、迁移、种子导入、前端构建、服务启动、健康检查与四页截图，退出码为 0，日志与
   产物留档。
2. **Given** 部署完成，**When** 用可自动化的真实浏览器加载四页，**Then** 控制台错误、
   失败请求、资源 404、字体加载失败、横向溢出均为 0，已知无害告警逐条登记。
3. **Given** 断网环境，**When** 打开四页，**Then** 字体、图标、图片全部本地加载成功，
   页面发出 0 个外网请求，视觉不塌陷。
4. **Given** 数据库或接口异常，**When** 打开任意页面，**Then** 显示明确降级/错误提示，
   不出现白屏或未捕获异常。
5. **Given** 固定种子数据，**When** 连续执行部署验证 3 次，**Then** 每次均成功，截图
   关键区域一致（允许时间戳与随机编号差异）。

### 用户故事 3 - 五个模块剥离为独立目录并各自自带验收证据（优先级：P1）

评审打开仓库，看到五个模块目录，每个目录有职责说明、对外契约、该模块的实现与可复现的
验收证据；模块之间只通过数据库对象、接口或文档化数据协作，没有隐式互相引用；单个模块
可被单独验收而不需要改动其他模块。

**Why this priority**：用户明确要求按图片的五个模块"尽量剥离并放在不同文件夹下"。
结构是可评审的交付物，也是课程"分模块负责 + 证据可核对"的前提。

**Independent Test**：按 `specs/002-ui-console-modularization/` 的模块索引进入任一模块
目录，只执行该目录 README 中的步骤，得到该模块的验收证据；再执行依赖边界检查确认无违规。

**Acceptance Scenarios**：

1. **Given** 仓库根目录，**When** 查看顶层结构，**Then** 五个模块目录按附录 A 的固定
   命名存在，每个目录含实现代码、模块 README 与证据目录。
2. **Given** 任一模块，**When** 按其 README 执行验收步骤，**Then** 可独立得到该模块的
   证据（提交/回滚用例、事件日志与 EXPLAIN、ER 与约束示例、规则版本与告警去重、视图
   口径与界面核对之一），无需修改其他模块代码。
3. **Given** 依赖边界检查，**When** 执行，**Then** 违规数 0、循环依赖 0；跨模块只出现
   公开契约调用。
4. **Given** 解耦完成，**When** 运行 001 既有测试与四页手工验收，**Then** 全部通过，
   接口返回与解耦前一致（在可比较范围内）。
5. **Given** 共享能力（脱敏、评分、配置、数据库连接、日志、构建部署脚本），**When**
   查找实现位置，**Then** 只在 shared 中定义一次，模块引用而非复制。
6. **Given** 迁移脚本与账号权限，**When** 查看归属，**Then** 只在 M1；M3 只拥有 ER 与
   约束规范，M5 只拥有视图口径与界面核对，边界无重叠。

### 用户故事 4 - 页面交互对真实数据生效且不出现假反馈（优先级：P2）

观察者切换时间范围、筛选告警、搜索攻击者、排序分页、标记已读、切换时间线类型、点击
现场刷新，页面数据随之真实变化，并显示加载与最后更新时间；点击原型中后端不支持的操作
时，看到明确的"演示未开放"说明，而不是动画或虚假成功。

**Why this priority**：原型是静态稿，多数交互只改样式或引用不存在的元素。若照搬，答辩
时一操作就暴露"假界面"，且会与 001 的"展示结果必须与数据库查询一致"冲突。

**Independent Test**：对每个可交互控件执行一次操作，核对网络请求、数据变化与最终数据库
状态；对禁用控件确认提示文案与不可点击状态。

**Acceptance Scenarios**：

1. **Given** 未读告警，**When** 标记已读，**Then** 写操作真实落库，列表状态、未读数与
   完成率同步更新，刷新后保持；写失败时显示原因且状态不变。
2. **Given** 批量标记已读，**When** 执行，**Then** 逐条真实写入并显示成功/部分失败明细，
   不得把失败项显示为已读。
3. **Given** 首页时间范围（今日 24H / 最近 7 天 / 全部历史），**When** 切换，**Then**
   指标与趋势按该范围重新取数，页面标明当前范围。
4. **Given** 攻击者列表，**When** 搜索 IP、选择风险档、选择意图、切换排序、翻页，
   **Then** 结果集与总数来自真实查询，排序稳定，空结果有空态。
5. **Given** 详情页时间线类型筛选，**When** 切换全部/仅认证/仅查询/仅规则命中，
   **Then** 只显示对应事件，计数与筛选结果一致。
6. **Given** 页头"现场刷新数据"，**When** 点击，**Then** 发起真实请求、显示加载态与
   最后更新时间，不得仅播放动画。
7. **Given** 无后端能力支撑的控件（导出取证报告、联动 DMZ 隔离、SQL 回放等），
   **When** 悬停或点击，**Then** 显示禁用态与"演示未开放"原因，或该控件不出现。

### 用户故事 5 - 视觉一致性可复核：基线截图 + 区域核对表（优先级：P2）

评审不靠主观印象判断"像不像"，而是拿到基线截图集、区域核对表与令牌抽查记录，能在
10 分钟内复核某页是否一致，并知道哪些差异被接受、为什么。

**Why this priority**：视觉一致性是用户的首要要求，但"看起来一致"不可验收。必须把它
转成可重复的核对材料，且这些材料同时是答辩证据。

**Independent Test**：按核对表逐项检查并重跑令牌抽查，确认结论可复现；改动界面后重跑
仍能得到一致或差异清单。

**Acceptance Scenarios**：

1. **Given** 固定视口与种子数据，**When** 采集四页截图，**Then** 每页各出 1440×900 与
   1920×1080 两张基线，命名含页面、视口、日期，存入模块证据目录与 `docs/`。
2. **Given** 基线截图与当前实现截图，**When** 并排核对，**Then** 区域核对表逐项填写
   一致/差异、差异理由与是否接受，不接受项有修复记录。
3. **Given** 令牌抽查（每页随机 20 处颜色、字号、圆角、间距），**When** 核对，**Then**
   100% 命中令牌集；未命中项登记为缺陷并修复。
4. **Given** 后续任何界面改动，**When** 重跑核对流程，**Then** 可在同一套材料上复现结论，
   不依赖个人记忆或截图之外的说明。

### 用户故事 6 - 原型自身缺陷被裁定并统一，四页作为一套系统而非四张孤立切图（优先级：P3）

原型由四张独立生成的页面组成，存在配色、编号、圆角、标题层级、引用元素不一致的问题。
重制时按统一裁定修正，并在文档中留下裁定理由，避免"每页各写一套"。

**Why this priority**：这些不一致不影响单页观感，但会破坏整体专业度，且在答辩追问
"为什么两页的同级告警颜色不同"时无法解释。它依赖前五个故事完成后再收敛。

**Independent Test**：对照附录 B 的裁定登记逐项确认已闭环；抽查跨页同级元素（严重度、
导航编号、容器圆角、页头结构）是否一致。

**Acceptance Scenarios**：

1. **Given** 原型跨页严重度配色不一致、导航第 4 项缺编号、详情页独有侧栏状态块、
   容器圆角 2/4/8px 混用，**When** 重制，**Then** 按附录 B 统一并登记理由。
2. **Given** 原型中引用不存在元素的死交互与死代码，**When** 重制，**Then** 实现或移除，
   不保留不可达路径与无反馈按钮。
3. **Given** 原型缺失一级标题与无障碍属性，**When** 重制，**Then** 每页有唯一一级标题，
   导航有当前项标记，图标按钮有可读标签。
4. **Given** 四页壳层，**When** 对照，**Then** 侧栏四项（编号 01–04）、页头控件、底部
   状态块在四页一致出现，仅激活项与主体内容不同。
5. **Given** 原型中写死的示例数字与自相矛盾的数据（时长与起止时间不符、编号日期不一致），
   **When** 重制，**Then** 全部由真实接口/视图生成，页面不出现硬编码示例值。

### 边界情况

- 断网/离线打开页面：公网字体、图标、Logo 不可用，页面必须自洽（本地资源），字体回退
  造成的字宽与换行差异登记为允许差异，不允许用图片替代文本。
- 浏览器缩放 110%/125%、投影分辨率 1920×1080 与笔记本 1440×900 切换：不得出现元素
  重叠、按钮被裁切、表格错行。
- 数据极端：0 告警、0 攻击者、单条会话、上百条事件、超长 SQL（超过 2KB）、趋势全为 0、
  分布只有一个类别：图表与列表必须显示空态或降级图形，不报错。
- 接口 503、超时、字段缺失：关键区域保留占位与错误提示，整页不白屏；重试入口可用。
- 时间语义：展示统一 UTC+8，跨日数据、结束时间早于开始时间等脏数据按原值呈现并在
  核对记录中登记，不在前端擅自修正。
- 页面数字与视图口径不一致（如"查询数"含义）：以视图/接口为准，页面标注来源视图名，
  不得为凑原型数字改口径。
- 批量已读部分失败：显式显示部分成功，未成功项保持未读。
- 详情页会话数量、关联会话数与列表实际条数不一致：由接口计算，禁止写死。
- 种子数据变化导致截图差异：基线截图必须由固定种子数据生成，并在记录中写明种子来源。
- 窄屏（<1024px）与移动端访问：按原型降级为单列/横向滚动，不承诺移动端专用体验。
- 截图与导出材料包含真实 IP 或口令：一律使用演示种子数据，脱敏横幅与掩码必须保留。
- 原型中的外链图片/字体在隔离环境被拦截：不得导致布局塌陷或空白占位。

## 需求 *(mandatory)*

### 功能需求

#### 控制台视觉与页面（UI）

- **FR-090**：控制台必须提供且仅提供 001 定义的四页——首页概览、攻击者列表、攻击者详情
  与时间线、告警列表；四页路由稳定，支持直接访问与刷新（不依赖从首页逐级点击进入）。
- **FR-091**：全局壳层必须统一：固定侧栏（品牌标识、诱饵监听状态条、四项导航及编号
  01–04、告警未读数徽标）、固定页头（目标实例标识、辅助分析标识、UTC+8 时钟、现场刷新、
  用户标识）、底部状态区（内核视图同步状态、当前权限、规格版本）。四页壳层结构一致，
  仅激活项与页面主体不同。
- **FR-092**：所有视觉取值必须来自 DESIGN.md 设计令牌：颜色（深色语义色板）、字号字阶、
  字体族（界面字体与等宽字体两族）、圆角档位、间距尺度。不得引入令牌外的颜色、字号、
  圆角或间距。
- **FR-093**：四级风险严重度（低/中/高/严重）必须在所有页面、徽标、图表、表格、时间线
  使用同一映射与同一组语义色；同一等级不得在不同页面换色。
- **FR-094**：版式必须遵循原型：宽屏为 12 栏网格、固定侧栏、固定页头；概览图表区与
  详情页画像/证据按原型比例分栏；中等宽度按原型降级重排；验收视口下不得出现横向滚动条
  与元素重叠。
- **FR-095**：关键组件外观与状态必须与原型一致：指标卡（含来源视图标注与趋势副标）、
  告警卡（未读/已读、等级光晕、证据代码框、元数据行、操作区、已归档态）、时间线
  （垂直连接线、事件类型图标、事件编号、SQL 三层结构、脱敏口令）、攻击者表格（双行
  IP 单元格、意图徽标、风险分条、等级徽标、下钻操作）、筛选工具条、分页栏、空态。
- **FR-096**：等宽字体必须仅用于技术标识（IP、SQL、时间戳、会话/事件/告警编号、规则
  编码、视图名、徽标），其余文本使用界面字体；时间戳统一 `YYYY-MM-DD HH:mm:ss` 并标注
  UTC+8；千分位、百分比、时长格式与原型一致。
- **FR-097**：双语命名约定必须保留：中文主标签 + 括号英文或等宽大写副标（如
  `会话识别码 (SESSION_ID)`、`CONNECT`、`RULE: R02`、`EVENT ID`），不得合并为单一语言。
- **FR-098**：页面出现的来源视图标注（如 `SRC: v_attacker_profile_summary`）必须与该
  数字的实际查询口径一致；不得标注未参与取数的视图。
- **FR-099**：脱敏与只读展示沿用 001：四页必须保留安全脱敏横幅与口令掩码，页面、截图
  与任何导出内容不得出现明文口令或可识别个人的真实信息。
- **FR-100**：每页必须处理空数据、加载中、接口失败与降级四种状态；空态提供可用的重置/
  修复入口；不得保留原型中引用不存在元素的死代码路径。
- **FR-101**：交互必须对真实数据生效：概览时间范围切换、告警状态/等级/类型/时间筛选、
  告警标记已读与批量已读、攻击者搜索/风险档/意图/排序/分页、时间线类型筛选、现场刷新。
  任何交互不得只改样式或播放动画而不改变数据。
- **FR-102**：原型中缺少数据或接口支撑的能力（取证报告导出、联动隔离、SQL 回放、
  假刷新动画等）必须按附录 B 处理：或真实实现，或以明确禁用态呈现并说明"演示未开放"；
  不得出现点击无反馈、假成功提示或界面承诺系统无法执行的动作。
- **FR-103**：控制台保持只读为主：唯一写操作是告警已读状态；写操作必须显示失败原因，
  并发更新以数据库实际状态为准。
- **FR-104**：页面必须适配答辩投影：正文对比度不低于 WCAG AA，页头、表头与关键数字在
  1920×1080 投影下可读；浏览器缩放 100%–125% 下不重叠。
- **FR-105**：每页必须有唯一一级标题与可访问语义（导航当前项标记、图标按钮可读标签、
  Logo 替代文本），不得因还原切图丢失标题层级。
- **FR-106**：页面不得依赖公网资源：字体、图标、图片、脚本全部本地提供；断网时四页
  视觉不塌陷，页面发出 0 个外网请求。

#### 部署与实际测试（DP）

- **FR-107**：验收必须在真实部署路径下完成：使用生产构建产物、由后端统一托管、单一
  访问地址；不得只在开发服务器上验收。
- **FR-108**：必须提供可重复的部署验证流程（一条命令或等价脚本）：准备数据库→执行
  迁移→导入种子→构建前端→启动服务→健康检查→四页截图与检查；退出码为 0，日志与产物
  入库。
- **FR-109**：必须用可自动化的真实浏览器在 1440×900 与 1920×1080 两档加载四页，采集
  控制台错误、失败请求、资源 404、字体加载失败与横向溢出；上述计数必须为 0，已知无害
  告警逐条登记。
- **FR-110**：必须产出视觉一致性核对记录：每页按附录 C 区域清单，在固定种子数据与固定
  视口下逐项核对，记录一致/差异与理由；一致项占比不低于 95%。
- **FR-111**：基线截图与核对记录必须留档到对应模块目录与 `docs/`，命名含页面、视口、
  日期，供评审与答辩复现。
- **FR-133**：控制台必须支持浅色/深色双主题，默认跟随操作系统 `prefers-color-scheme`：
  系统外观切换时界面实时生效（无需刷新）；页头提供圆角矩形切换按钮，可在跟随系统 →
  浅色 → 深色间循环，手动选择持久化并在刷新后保持；首屏不得出现主题闪烁。
- **FR-134**：两套主题必须共用同一组语义令牌（颜色、图表系列色、阴影由 CSS 变量定义，
  深色为默认、浅色按 light 原型覆盖），组件与图表不得写死色值；浅色主题按
  `ux/stitch_database_honeypot_analytics_console_light/` 的色板与层级实现，两套主题下
  正文对比度均不低于 WCAG AA。
- **FR-112**：必须核对页面数字与数据库/视图结果：每页至少 3 组抽样，SQL 结果与页面
  展示差异为 0，核对用的查询必须可直接运行。
- **FR-113**：必须验证降级路径：数据库或接口不可用时页面显示明确降级提示，不出现白屏、
  未捕获异常或静默空数据。

#### 模块解耦与目录结构（MD）

- **FR-114**：仓库根必须包含五个模块目录，命名固定并与附录 A 一致：`m1-transaction-integration`、
  `m2-decoy-capture`、`m3-er-constraints`、`m4-rules-derived`、`m5-views-console`。
- **FR-115**：每个模块目录必须自包含：该模块拥有的实现代码、模块 README（职责、对外
  契约、依赖、验收步骤、证据索引）与验收证据（脚本、查询、截图、记录）。
- **FR-116**：共享平台能力（配置、日志、数据库连接与数据模型契约、脱敏工具、通用查询
  工具、构建与部署脚本）必须集中在独立 `shared` 目录；模块只能依赖 shared，不得依赖
  其他模块的内部实现。
- **FR-117**：模块之间只允许通过公开契约协作：数据库表/视图、HTTP 接口、命令行入口或
  文档化数据文件；跨模块内部函数与内部组件的直接引用必须禁止。
- **FR-118**：依赖关系必须无环且方向固定：接口层与事务写入由 M1 提供，M2 的事件写入经
  M1 事务入口，M4 的分析在同一事务内由 M1 调用，M5 只读消费 M1 接口与视图；具体方向在
  计划阶段细化为依赖矩阵并写入各模块 README。
- **FR-119**：产物所有权必须唯一且无重叠：迁移脚本、账号权限、事务入口归 M1；ER 模型与
  约束规范归 M3；规则定义、评分、告警去重归 M4；诱饵协议与采集归 M2；视图口径、控制台
  与界面核对归 M5。任何模块不得越界修改他人拥有的产物。
- **FR-120**：数据模型变更流程固定：M3 设计（ER/约束）→ M1 迁移与回滚演练 → M2/M4/M5
  适配；未经 M3 评审的模型变更不得进入迁移。
- **FR-121**：现有代码搬迁必须保留版本历史的移动方式，并同步更新架构文档与目录映射；
  解耦后不得存在两套同能力代码并存。
- **FR-122**：必须提供自动化依赖边界检查（导入边界/目录边界），出现跨模块内部依赖或
  循环依赖即失败；检查纳入验收流程。
- **FR-123**：解耦不得造成功能回归：001 既有测试全部通过；四页行为与接口返回与解耦前
  一致（在可比较范围内）。

#### 模块验收证据（EV）

- **FR-124**：**M1 证据**——提交与回滚用例（正常提交前后数据快照、注入失败后相关数据
  与事务前一致）、数据库账号职责说明与实测（迁移/读写/只读账号的权限边界与越权被拒

- **FR-126**：**M3 证据**——关键实体关系图（可版本管理源文件，与 DDL 一致）、主外键与

#### 安全与约束（SF）

- **FR-130**：安全红线与脱敏要求与 001 一致：只允许在授权的隔离环境运行，不得展示明文
  凭据、真实个人信息或可用内网信息；新增截图与核对材料同样适用。
- **FR-131**：原型中的演示文案与控件不得暗示系统具备主动反制、漏洞利用或隔离联动能力；

- **FR-132**：解耦与重构不得降低权限边界：只读账号、写入账号、迁移账号分离的要求保持

### 关键实体 *(涉及数据时必填)*

- **模块包（M1–M5）**：五个自包含交付单元；每个拥有自己的实现、契约说明与证据，依赖
  方向固定、边界可自动检查。
- **共享平台（shared）**：跨模块的公共能力与约定，包括配置、日志、数据访问契约、脱敏、
  部署与构建脚本；被模块引用而非复制。
- **设计令牌集**：颜色、字阶、字体族、圆角、间距的唯一取值来源，是视觉一致性的判定基准。
- **页面与区域**：四个页面及其可核对区域（附录 C），是视觉验收的最小编号单位。
- **视觉基线**：固定种子数据与固定视口下采集的四页截图集合，与区域核对表配套。
- **区域核对记录**：每个区域的对照结论、差异理由与接受状态，构成视觉一致性的可审计证据。
- **模块证据包**：附录 A 右列要求的证据集合，含脚本/查询、实测输出与截图。
- **部署验证记录**：一次真实部署的步骤、命令、退出码、健康检查结果、浏览器检查计数与
  截图路径；可重复执行并留档。
- **原型差异裁定登记（附录 B）**：原型不一致项的统一裁定与理由，避免逐页各自解释。

## 假设

- **技术选型不在本规格锁定**：控制台的技术栈（是否沿用现有组件库、是否改用样式工具类
  方案）由 `/speckit-plan` 决定；本规格只约束可见结果与可验收证据。视觉一致性优先于
  沿用现有组件库的默认外观。
- **权威来源**：DESIGN.md 是颜色语义角色、字阶、间距、圆角档位与组件规范的权威；四张
  原型截图是布局、区域顺序与组件形态的权威。两者冲突按附录 B 裁定：语义角色的分配按
  DESIGN.md（严重度四级色、主色/次色用途），具体表面色值以截图实际使用的 M3 令牌为准
  （附录 B 第 1 条），实现阶段同步把 DESIGN.md 的旧色板段落更新为新值。
- **数据来源不变**：四页数据沿用 001 已实现的视图与接口，不新增业务聚合；原型中的示例
  数字由固定种子数据复现，不要求页面数字与原型数字相同。
- **一致性判定方式**：以"逐区域核对 + 令牌抽查"为准，不做像素级自动 diff 门禁；字体
  回退导致的度量差异允许登记为可接受差异。
- **离线演示环境**：答辩与评审环境为隔离网络、无公网，所有字体与图标必须本地提供；
  原型中的 Google Fonts、CDN 脚本与外链 Logo 不得进入交付版本。
- **模块划分依据**：五模块严格按附录 A 划分；现有分层代码按能力归入模块，共享平台代码
  集中到 `shared`；归入方式在计划阶段细化，但不得违反 FR-116 至 FR-119 的所有权约定。
- **部署测试范围**：课程语境下的"实际部署测试"指在本机或实验机完成一次真实构建+部署+
  浏览器验证并留证，不要求公网部署或完整容器编排。
- **原型未接数据的能力**：默认不实现真实业务，只保留禁用态与说明（附录 B 已逐项裁定）；
  若计划阶段确认成本可控，可作为可选增强实现。
- **AI 辅助为可关闭增强**：控制台仅保留"AI 辅助分析"标识与禁用入口，001 的 AI 接口
  不作本规格验收对象。

## 术语与口径

- **原型**：`ux/stitch_database_honeypot_analytics_console/` 下的四页深色静态设计稿与
  DESIGN.md 设计系统。
- **设计令牌**：颜色、字阶、字体族、圆角、间距的命名取值；视觉一致性的判定基准。
- **视觉基线**：固定种子数据与固定视口下采集的四页截图集合。
- **区域核对表**：按附录 C 区域清单逐项记录一致/差异与理由的验收表。
- **部署验证流程**：从数据库准备到四页截图的一条可重复命令链路。
- **模块包**：附录 A 中的五个交付单元；"解耦"指模块只通过公开契约协作。
- **共享平台（shared）**：跨模块公共能力集合；不是第六个业务模块，不承载业务规则。
- **边界检查**：自动检测跨模块内部依赖与循环依赖的检查。
- **假反馈**：界面提示成功或数据变化，但实际未写入、未查询或未生效的交互。
